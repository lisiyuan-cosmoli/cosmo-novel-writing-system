6.0 / Choose a mode for your story

Look at what keeps readers going,
one stretch at a time.

New books default to General mode, which focuses on reading expectations and development over a story phase. Relationships, new understanding, and experience can drive the story, and a natural ending is allowed. Progression and Conflict mode adds checks for opponents, advancement, and satisfying payoffs. Older engine cards without a mode field retain their original interpretation. Upgrading does not force older books without an active engine to add cards.

A batch defaults to three chapters; you can also work one chapter at a time. The project can configure a batch limit of up to five. Review the recent reading experience every three chapters, and the broader structure every twelve chapters or at an arc ending. Propose improvements or explain why the existing plan should stay. Read the manuscript before talking with the author. Research into comparable ranked books is optional; give a reason when skipping it, and do not repeat the author interview in the same review cycle.

The full review includes the short review due at that point. The program identifies pending work; the author and AI do the reading, research, and judgment. These checks are not literary quality scores.

Before you start

What it does.
Where its limits are.

Can I write a novel on this website?

This site introduces the system. Your AI assistant handles drafting, research, and revision; Python tools handle the local workflow. The core scripts can run offline. Network access and how your material is handled depend on the AI service you choose.

Does it call paid APIs? How much will it use in tokens?

The system has no built-in paid API and does not call a model for you. If you use an external AI assistant, any charges and billing rules come from the service you choose.

Even the same text can use different numbers of tokens because models tokenize it differently. The context you include, the reading level, and the number of exchanges also affect usage. Character budgets in this system limit the material assembled into a package; they are not token or cost caps. Check actual usage and charges with your AI service.

Which AI tools can I consider besides Codex?

You can keep using Codex or try one of these tools. They offer different entry points, and some have several interfaces.

Desktop workspaces: WorkBuddy; Claude Code also offers desktop, editor and terminal interfaces.

Agents in an editor: Cursor Agent, GitHub Copilot (VS Code agents), and Cline.

Command-line tools: Codex CLI, Claude Code and Gemini CLI. Cline also has a CLI.

This release has only been tested on macOS and requires Python 3.9+. Windows, Linux, WSL and other environments have not been verified. To use COSMO there, adapt and test it yourself, including saving, backup and recovery, before using it for your manuscript. The agent checks the environment. Check that the current mode can read the whole project, run Python commands and save changes. Chat attachments alone are not enough. For cloud workspaces, confirm how to export or synchronize the complete project. Check these capabilities separately if you use another file-enabled Claude mode.

These links are official sources, checked on September 23, 2026. The list is not a COSMO compatibility certification or an assessment of writing quality. Try a separate copy first. A tool supporting Windows does not make COSMO support native Windows; costs and token usage also vary by tool and model.

Does the English website mean the whole system works in English?

The website is fully available in Chinese and English. The system core, templates, and user documentation are still primarily in Chinese. The English website does not mean the core has been localized or promise a fully English operating experience.

Under the project licenses, you can adapt it for other languages. This involves adapting prompts and templates, Chinese paths and field parsing, and language checks, then validating the changes with an example project.

Will reviewing every three chapters make every story move too fast?

The review asks what keeps a reader engaged. Quiet chapters can move forward through a new feeling, a changed relationship, or fresh information. Explain where a passage loses interest before deciding to speed it up. Avoid adding twists and conflict mechanically.

The program flags pending reviews; the author and AI reach conclusions through reading. Effective prose does not need changing just to fill in a form.

Do I have to research rankings every twelve chapters?

Research into the text of ranked books is optional; explain why if you skip it. If you do it, an AI assistant with browsing access selects comparable works and reads legally accessible consecutive passages. Record the sources, dates, and reading scope, then extract general methods that may help this book.

If access is limited, record what was actually read and what would be needed for a follow-up. No follow-up task is automatically added to the next cycle. The tools do not browse automatically or treat a synopsis as a read manuscript.

Will importing a voice sample immediately change the adopted settings?

Selected samples enter a candidate first: INIT for a new book, REVISE for revisions to an existing book. Complete the sample analysis, then check and approve the same digest through the existing workflow before the adopted sample changes.

For an existing book that needs its initial setup completed, you can explicitly choose INIT. If both types of candidate exist, the tool requires you to choose which one to handle. Voice profiles, genre plugins, and creative modes are separate choices.

What do retained candidates and backups preserve?

After a successful chapter commit, 6.0 keeps the candidate in a retained-candidate directory and reports its location. Content saved during the commit can be checked there. It does not automatically become part of the committed manuscript, and the earlier approval does not cover it.

A regular backup preserves currently effective content, excluding candidates, retained candidates, reading packages, and transaction history. Save important unused material separately. A snapshot of an interrupted transaction preserves the scene but does not guarantee a consistent book can be restored from it; check the records before recovery.

Can I change genres or AI tools and keep working?

Agreements and progress are stored in local files, so another AI assistant that works with local files can continue. There are 4 optional genre plugins: mystery, romance, science fiction and fantasy, and serialized web fiction. You can also use none.

When changing assistants, reread the book's entry instructions and current state. Later decisions should still follow what the author has confirmed.

Will an update overwrite my book?

For a new book, duplicate an unused template saved earlier or download a fresh copy. Keep using the existing folder for your current book. Synchronization checks the recorded installation baseline and stops by default on unknown differences or local changes. Recognized book-specific customizations follow the preservation rules.

A system update does not adopt new story plans or revise the book for the author.

What has been verified so far?

The 6.0 release self-test passes 446 / 446 checks covering initialization, reading packages, commits, revisions, review records, synchronization, recovery, and other software workflows.

Passing software checks does not prove a novel is good. Characterization, language, and reader engagement still need actual review and reader feedback. See the acceptance report (Chinese) and known limitations (Chinese).
