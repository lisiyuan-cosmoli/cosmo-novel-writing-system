工作原理 / VERSION 6.0

一章小说，
是怎样写进整本书的。

资料怎样流动，审查怎样影响后文，改动怎样被确认和保存。这一页讲清 COSMO 的每一个环节。

01系统组成02逐章循环03阶段审查04确认与保存05运行反馈06隔离与恢复07能力边界

01 / 系统组成

作者、AI 与工具，
各司其职。

作者定方向、做取舍；AI 负责研究、起草与改稿；本地工具把准备、检查与保存串成一条完整的流程。被采用的内容，最终写入这本书自己的文件。

所有正式操作都通过 novel.py 执行。模型与流程相互独立：换用其他支持本地文件的 AI 工具，也能从本书入口与当前状态继续。

02 / 逐章循环

写定的每一章，
都是下一章的起点。

开书时，先接收你已有的材料，推敲故事方向、结构与文风，确认后完成初始化。正式写作默认三章一批，也可一章一批，最多五章；每一批都走同一条循环。

候选区：可以尝试，也可以放弃

试算在项目副本中进行。未通过检查的候选退回修改；你可以继续调整，也可以保留原稿。

正式项目：确认后才算数

只有经你确认、并通过保存前复核的改动，才会写入正式文件。探索稿与未采用的方案，不会计入正文、进度或人物事实。

文风样本同样先进入候选：开书阶段使用 INIT，已开书的修订使用 REVISE，完成样本分析并经你确认后才写入。两轮检查依次关注阅读动力、连续性与语言；每批另做独立审稿，一段剧情收尾时再整体通读。

03 / 阶段审查 · 6.0

大纲为故事领路，
正文也在修正大纲。

审查按实际定稿的阅读顺序计数。第三、六、九章回看近期体验，第十二章复盘阶段结构，并包含当次小审查。

沿用原有的大纲与候选流程

开书阶段沿用 INIT，已开书沿用 REVISE。确定的调整写入原大纲与相关章卡，再影响后续写作；逐章候选的修改范围保持不变。

正文变了，审查也要重来

审查会记录覆盖的章节顺序与正文摘要。旧章被改或顺序变化时，系统会提示重新检查；只准备了任务、刷新了资料或登记了延期，都不算审查完成。

程序负责识别到期的审查、记录覆盖范围。等待你回复期间不算已交流，本轮已有答复则直接接续。局部修复与阶段整体判断分开说明；阅读、交流与研究的质量，仍需实际核对。

04 / 确认与保存

你确认的那一版，
就是保存的那一版。

系统为每份候选计算内容摘要，并记录试算时相关文件的状态。保存前再核对一次，确保稿件没有在确认之后被改动。

候选稿改成了版本 B，需要重新试算并确认新的摘要；相关正式文件发生变化，则要基于当前文件重新核对，再试算与确认。

内容摘要用来锁定你确认的对象。它无法证明你是否逐字读过，也不能代替对人物、语言与因果的审阅。

05 / 运行反馈

每一个问题，
都留下完整的处理记录。

写作中出现的误解、返工或流程卡顿，由 AI 从可见的对话与已有证据中整理成记录：发生了什么、如何判断、怎样处理、如何验证。

  1. 01 / 来源

    留下具体证据

    记录对话摘录、工具输出或 AI 的观察，注明来源与可见范围。

  2. 02 / 判断

    分清问题性质

    区分创作选择、执行偏差、模板限制与程序缺陷，保留有待验证的解释。

  3. 03 / 处理

    写明调整与范围

    记录采取的修正与受影响的环节；决定不升级系统，也写明理由。

  4. 04 / 验证

    让结论接受复查

    未关闭的问题进入下一轮准备，对照实际改稿与阅读反馈验证；再次出现时沿用同一编号，保留完整历史。

↳ 本书问题记录 → 归纳通用经验 → 评估系统改动 → 在后续使用中验证

纳入归档与备份

运行记录保存在本书的追加式日志中，并纳入备份。它不改动创作提交的记录，也不会整份塞进每章的读取包。

证据有边界，作品留在本书

系统不会自动抓取全部聊天或其他任务，AI 只整理自己实际看到的证据。更新系统时，只提取可复用的方法与规则。

06 / 作品隔离与持续升级

系统持续升级，
作品的积累原封不动。

下载的文件夹可以直接用来写一本书。开写前留一份空白副本，以后开新书直接复制，或重新下载。已有作品继续使用原文件夹；更新工具前，系统会先核对安装记录与本地改动。

保存中途被打断，怎样恢复？

整笔写入尚未验证完成

系统保留未完成的现场，暂停后续写入。你查看涉及的文件并明确同意恢复后，才会退回保存前的状态。

已验证通过，停在收尾阶段

根据中断位置补完提交记录与历史，保留已验证的内容。仅查看状态，不会触发恢复。

能捕获的写入错误会自动尝试回退；强制中断后的恢复必须明确执行，恢复前请先核对相关记录。

候选存根：保留提交现场

章节成功提交后，候选会整体移入存根目录，结果中给出位置。提交期间新保存的内容可在此核对；存根不会自动成为正式稿，也不属于下一次已确认的候选。

常规备份：保存当前有效内容

不包含候选、存根、读取包与事务历史，未采用但想保留的内容请另行保存。中断时的现场备份会单独标明，不保证内容前后一致，也不能代替原项目的恢复记录。

6.0 继续使用 schema 2 与原有的 INIT / REVISE 流程。新书默认使用通用模式，围绕读者期待与阶段发展；选择升级对抗模式后，才要求对手与升级设计。旧版本的设定卡沿用原有解释，未启用该功能的旧书无需补填。升级本身不会重开旧书，也不会自动采用新的故事方案。

07 / 能力边界

流程可以核对，
好故事仍要靠认真阅读。

技术手段让文件、版本与记录更可靠；作品有没有生命力，还要回到真实的段落与阅读体验中判断。

程序检查

  • 必要资料、文件结构与记录是否齐全
  • 候选摘要与确认对象是否一致
  • 相关文件、事务与审查覆盖是否变化
  • 同步改动是否涉及本地修改

作者、AI 与读者的判断

  • 人物动机与故事因果是否可信
  • 文风、场景与叙述是否贴切
  • 节奏与期待能否带来阅读动力
  • 研究与改稿是否真正让作品变好

软件验证通过，只代表对应的流程检查通过。文学质量与长期写作收益，需要作品审阅、真实反馈和持续使用来检验。
