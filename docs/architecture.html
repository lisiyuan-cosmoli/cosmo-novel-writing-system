系统图解 / VERSION 6.0

一个故事的背后，
是一套怎样的协作。

沿着资料与决策的流向，看一章如何写成、一次审查如何影响后文，以及作品怎样在持续更新中保留自己的依据。

01 / 系统组成

创作判断、流程执行、
作品记录，各有位置。

作者确定方向并阅读取舍，AI 助手协助研究、起草与改稿。本地工具把准备、检查和保存接起来，作品文件保留被采用的内容。

执行入口统一为 novel.py。模型能力与本地流程分开，换用兼容本地文件工作的助手时，仍可从本书入口和当前状态接续。

02 / 逐章循环

正式写出的内容，
决定下一章的起点。

开书时先接收已有材料、推敲方向与结构，再确认初始化候选。正式写作默认三章一批，也可一章一批；项目可调整批次上限，最多五章。每一批沿同一条循环推进。

候选区 · 可以尝试与舍弃

试算在项目副本中进行。未通过检查的候选回到修改环节，作者可以继续调整，也可以保留原稿。

正式项目 · 采用后才成为依据

确认并通过保存前复核的改动进入正式文件。探索稿和未采用方案不自动计入正文、进度或人物事实。

选定的文风样本也先暂存候选：开书使用 INIT，已开书修订使用 REVISE。完成样本分析并批准同一摘要后，才写入正式样本。两遍检查依次关注追读体验、连续性与语言；每批独立审稿，弧末再通读。

03 / 阶段审查 · 6.0

大纲为故事领路，
正文也让大纲修正方向。

审查以实际定稿的阅读顺序计数。三、六、九章关注近期体验，十二章回看阶段结构，并包含本次小审查。

复用原有大纲和候选流程

开书阶段沿用 INIT，已开书沿用 REVISE。采纳的调整进入原大纲与相关章卡，再影响后续写作。逐章候选的可修改范围保持原有约束。

审查依据会随正文变化失效

记录覆盖的章节顺序与正文摘要。旧章或顺序变化会提示重新检查；只准备任务、刷新资料或填写延期，不会算作审查完成。

程序负责识别待办与记录覆盖范围。等待作者回复不记为已交流，已有本轮答复直接接续。局部修复与阶段整体判断分别说明；阅读、交流和研究的质量仍需实际核对。

04 / 确认与保存

确认的那一稿，
保存时仍须是同一稿。

系统为候选计算内容摘要，并保存试算时的相关文件基线。保存前重新核对，避免稿件变化后仍沿用旧确认。

候选稿改为版本 B，需要重新试算并确认新摘要；相关正式文件变化，则需要基于当前文件重新核对，再试算与确认。

内容摘要用于绑定批准对象，不能判断作者是否实际读过，也不能代替对人物、语言和因果的审阅。

05 / 从真实使用中改进

一次问题，
留下完整的处理来路。

运行中遇到的误解、返工或流程阻塞，由执行助手从可见对话和已有证据中整理。每条记录区分发生了什么、怎样判断、如何处理以及怎样验证。

  1. 01 / 来源

    留下具体证据

    记录对话摘录、工具结果或助手观察，注明来源位置与可见范围。

  2. 02 / 判断

    分清问题性质

    区分作品选择、执行偏差、模板限制和程序问题，保留待验证的解释。

  3. 03 / 处理

    写明调整与范围

    记录采取的修正、受影响的环节，也记录不升级系统的理由。

  4. 04 / 验证

    让结论接受复查

    未关闭问题进入下一轮准备。对照实际改稿与阅读反馈验证；复发时接续同一编号，保留历史。

↳ 本书问题记录 → 归纳通用经验 → 评估系统改动 → 在后续使用中验证

进入归档和备份

运行问题保存在本书追加式记录中，纳入备份。它不改写创作提交的 HEAD，也不会整份塞进每章读取包。

证据范围清楚，作品数据留在本书

系统不自动抓取全部聊天或其他任务。助手整理自己实际看到的证据；更新母版时，只提取可复用的方法和规则。

06 / 作品隔离与持续升级

系统可以演进，
作品保留自己的积累。

下载的文件夹可以直接用于一本书。开写前也可以留一份空白模板，以后开新书时复制使用，或重新下载。旧书继续使用原目录，更新工具时先检查安装基线与本地差异。

保存意外中断后，怎样恢复？

尚未完成整笔写入验证

系统保留未完成事务现场，暂停后续写入。查看涉及文件并明确执行恢复后，根据记录回到保存前状态。

已验证通过，进入提交收尾

根据中断位置补完提交记录与历史更新，保留已验证通过的内容。查看状态本身不会触发恢复。

能捕获的写入错误会尝试回退。强制中断后的恢复需要明确执行，恢复前应先核对相关记录。

候选存根 · 保留提交现场

成功提交章节后，候选原子移入存根，结果会给出位置。期间新保存的内容仍可核对；存根不自动成为正式稿，也不属于下一次已批准的候选。

常规备份 · 保存当前有效内容

不含候选、存根、读取包和事务历史。需要保留的未采纳内容另行保存。中断事务的现场备份单独标明，不保证内容一致，也不能代替原项目的事务恢复记录。

6.0 继续使用 schema 2 与原有 INIT / REVISE 流程。新书默认通用模式，围绕阅读期待和阶段发展；选升级对抗后才要求对手与升级。没有模式字段的旧卡保持原解释，未启用引擎的旧书不被迫补卡。升级本身不重开旧书，也不自动采纳新故事方案。

07 / 判断的边界

流程可以核对，
故事仍要认真地读。

技术保护让文件、版本和记录更可靠。作品的生命力，还要回到真实的段落与阅读体验中判断。

程序检查

  • 必要资料、文件结构与记录是否齐全
  • 候选摘要与批准对象是否一致
  • 相关基线、事务和审查覆盖是否变化
  • 同步改动是否涉及本地差异

作者、AI 与读者判断

  • 人物动机和故事因果是否可信
  • 文风、场景与叙述是否合适
  • 节奏与期待是否带来阅读动力
  • 研究与改稿是否真正改善作品

软件验证通过，只说明相应流程检查通过。文学质量与长期写作收益，需要作品审阅、真实反馈和持续使用来验证。
