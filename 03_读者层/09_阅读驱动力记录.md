# 09 阅读驱动力记录

> 这张表记录真实读者的反应。AI 与作者已经知道故事设计，无法替代第一次接触文本的读者。

无人参加时保留为空，不把模型扮演读者的反馈填成真人记录。模型复读可以另记，并注明它是否看过大纲、设定和作者解释；更换提示词不等于获得独立意见。

## 使用方式

配合三章小审查或十二章大审查按需做一次，也可以在阶段结束、重大转折和初稿完成等位置执行。可与 outline 的阶段结构复盘合并，本表仍只记录真实读者反馈；没有读者时，结构复盘继续记录作者或代理判断。

1. 先写下你预期读者在意的人、问题和承诺
2. 保存预期后再把干净正文交给没有听过剧情的人
3. 不介绍设计意图
4. 记录读者原话、完成时间和是否主动索要后文
5. 把单次结果当作线索，重复出现或多人一致的信号再进入改稿

需要比较两个改稿版本时，使用 `03_读者层/10_试改记录_空白模板.md` 的副本，并按 `02_检查层/14_写作质量试验.md` 隐藏来源、轮换顺序。普通阅读不必做版本比较。记录实际阅读用时；从收稿到回复的时长只能表示反馈等待时间。

## 检查流程本身是否有用（可选）

每完成一个短段，回看流程审计里的准备与返工耗时，并记录哪项检查发现了具体问题、哪些字段只是重复填写。每轮只调整一项非安全流程，保持提交保护不变；下一段再比较耗时、返工原因和读者反应。章节内容不同会影响结果，不能把一次比较写成确定的因果结论。

## 平台数据（上线后）

上线后，平台的章节完读与追读数据是判断“读者会不会点下一章”的头号信号，弧末复盘先看它，再看代理判断。只写实际看到的数字，注明来源、日期、观察范围和口径；缺曝光或点击等分母时不推算比率。

| 日期 | 来源与口径 | 章节范围 | 完读率或追读数 | 掉点最明显的章节 | 当时的章末钩子类型 | 下一步只做的一项调整 |
|---|---|---|---|---|---|---|
| | | | | | | |

掉点的位置比读者的解释更可信，但它不告诉你怎么改。先对照那一章的章末钩子和回报间隔，再决定要不要改后续弧卡。
