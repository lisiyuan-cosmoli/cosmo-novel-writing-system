# 题材插件说明

核心流程可以独立服务任何题材。插件只增加某类小说常用的设定表、运行表和逐章检查，不修改核心文件。

## 两层：逐章检查与题材手册

| | 在哪 | 进读取包吗 | 什么时候看 |
|---|---|---|---|
| **逐章检查** | `02_检查层/插件/<id>.md` | **进**，作为 CONTROL | 每章自动跟包进来 |
| **题材手册** | `04_题材插件/<题材>.md` | 不进 | 写不下去或吃不准时调阅 |

分两层是因为：每章都带四份完整手册，是拿最贵的预算去装大部分章节用不到的资料；但"不进包"不能变成"没人读"——v1 的题材指导就是这么消失的，它在文档里，而逐章写作只会读取已装配的上下文。

所以每章必须执行的部分蒸馏进检查文件（**每份不超过 1200 字符，母版检查盯着这条线**），判断依据留在手册里，检查文件末尾指向对应手册。

```text
python3 novel.py guide                 列出可用手册
python3 novel.py guide suspense        打印某一份
```

## 插件里的数字都是警报值

除了明确标为硬规则的少数几条，插件里所有数字都是**警报值，不是硬规则**。它们触发一次检查，不禁止越线。越线了就说明理由并记一笔。

核心系统明确反对把创作判断量化成固定数字，插件不能在这一点上自作主张。

## 查看插件

```text
python3 novel.py plugin list
```

## 明确不用插件

```text
python3 novel.py plugin none
```

## 安装插件

```text
python3 novel.py plugin install suspense
python3 novel.py plugin install romance
python3 novel.py plugin install speculative
python3 novel.py plugin install serial
```

一本书可以组合多个插件。安装器遇到同名且内容不同的文件会停止，不会覆盖项目数据。

## 卸载插件

没有项目数据时可以直接卸载。已经填写的数据需要 `--force`，工具会先把原文件归档到 `06_归档/插件/<插件名>/<时间戳>/`，路径结构与项目内一致，再从运行目录移除。

```text
python3 novel.py plugin uninstall romance
python3 novel.py plugin uninstall romance --force
```

插件是否启用只读取 `project.json`。项目配置里的旧勾选框仅供迁移器识别旧项目。

卸载掉最后一个插件后，项目会回到**明确不启用插件**的状态（`plugin_decision` 为 `none`），核心流程仍然完整。这不是「未表态」，不会再拦住读取包。
