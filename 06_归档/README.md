# 归档

这里保存不会进入日常读取包、但后续仍需要追溯的创作记录。

- `章节卡_K0001.md` 保存定稿走向与用户输入
- `梗概_K0001_ABC.md` 保存候选走向与选择理由
- `废弃_K0001_v1.md` 保存确有追溯价值的废弃版本
- `流程审计.md` 保存每章模式、步骤状态、耗时与问题来源
- `修订核对_<摘要>.json` 由全局修订自动保存关联核对范围、基线摘要与结论；不手写，不当作事实账本
- 插件归档只在相应插件启用后出现

归档文件使用永久 ID。展示章号变化时不改文件名。

每个阶段可以把反复出现的选择理由压缩成少量写作偏好，确认后写入风格样本。原始记录继续留在本目录。


## 3.10 开书探索与文风推荐

开书时先提供已有研究报告、故事方案、参考作品和试写；没有材料再按需研究。已有方案或明确文风可以沿用，不新增研究门槛。`discover --prepare` 准备可编辑记录，`discover --import <文件>` 保存原始材料副本，`discover --prompt` 给出研究任务。`voice --recommend` 给出文风推荐任务，两者本身都不联网或生成推荐结论。

需长期保留时使用 `discover --stage`，研究记录与原始材料进入现有 foundation 或 revise 候选；按原有完整摘要批准后才正式归档并进入备份。研究报告、文风推荐及材料清单不整份进入逐章读取包，只有作者采纳的简短约定进入创作意图与风格样本。方法与空白模板可以升级，填写后的记录和原始材料不被同步覆盖。

具体方法见 `02_检查层/15_开书探索与文风推荐.md`。导入只能证明材料保存成功，不能证明已经阅读、内容可信或作者已采纳。推荐可能不合适，研究可能耗时；可以否决、暂缓、缩小范围或跳过，不能保证提升文学质量或收入。

## 结构论证与复盘

`结构复盘.md` 保存最近一轮论证范围、具体依据、选择理由、影响与下次触发条件，由 outline --prepare 放入原 INIT 或 REVISE 候选。它属于项目数据，sync 不覆盖。资料版本是字节依据，不能证明阅读或结构质量；采用的安排仍以原大纲等创作文件为准。正式记录进入备份，候选尚未备份。
