# 01 固定设定（故事圣经）

> **性质**：项目开始时填，之后**极少**改。这里放的是"不会因为剧情推进而改变"的东西。
> 会变的东西（人物此刻在哪、知道什么、和谁闹翻了）全部放 `04_状态快照.md`，不要写在这里。
> **建议篇幅：3000 字以内。** 超了就是把该进快照的东西写进来了。
> **每次生成正文都会完整注入这份文件**，所以它必须精确、无冗余。

## C. 世界规则

| 项 | 内容 |
|---|---|
| 时间与地点 | |
| 社会/技术背景 | |
| 本书成立的特殊规则（若有） | |
| 规则的代价 / 边界 | |
| 明确**不**成立的事（防止后期开挂） | |
| 正文里怎么叫（若有） | |

> 最后一行最重要。写清楚"什么做不到"，比写"什么能做到"更能防崩。
>
> 规则按条款写是为了堵漏洞、方便核对；系统提示、对话和叙述用人物日常的说法。条款里的限定词写进“正文里怎么叫”，不照搬进正文。合成例子：规则写“需完成装配并通过复核后予以奖励”，通知可以说“装好了，奖励已发放”。
