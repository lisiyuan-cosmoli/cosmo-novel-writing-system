# 08 两遍检查

> 4.0 起四遍检查合并为两遍。文件名沿用，便于旧项目同步。
>
> 顺序：**两遍都只诊断 → 统一修改一次 → 从头连读复读一次**。边查边改会让前面确认过的时间线和信息顺序失效。
>
> 一批三章时，第一遍把三章连着读；逐章写作时按一章执行。已启用插件的追加检查跟着读取包进来，在第一遍一并执行。

## 第一遍　追读

```text
先把这一批从头到尾连着读一遍，记下想跳过、开始能猜到、需要回看的位置。然后逐条回答，每条指出正文位置：

先按引擎卡的创作模式检查；无模式栏旧卡沿用升级对抗，未启用引擎的旧书按已有创作意图。
1. 承接与发展：开头、中段、结尾是否实现章卡安排？通用模式可以推进关系、认识或体验，
   自然收束可以成立；不强制每章危机、胜负或不可逆事件。
2. 阅读期待：本批怎样实现本书承诺？升级对抗模式另查所选升级阶梯与爽感单元的兑现。
3. 人物：行动、观察与判断是否符合当时欲望和知情？有选择时检查理由与后果，不强迫每章有代价选择。
4. 阶段作用：本批在关系、认识、处境或体验上怎样积累、深化或收束？不把数值变大当作唯一发展。
5. 悬念账：开了、推进了、兑现了哪些问题？超过 8 章未推进的是否仍应保留？
   3—5 个活动悬念只供升级对抗模式参考，不为凑数增加问题。
6. 末句检查：连读每章最后 300 字，说明期待怎样延续或体验怎样完成；缺少悬崖式钩子不自动判错。
7. 删章测试：拿掉本章，会损失什么阅读价值？因果仍通不能单独成为删章理由。
8. 对照弧卡：实际写成的与批准的章节拍有没有偏离？偏离要么改正文，要么把弧卡修改交作者看。

只列问题和位置，不改正文。
```

`novel.py hooks <批次>` 会把每章末尾和悬念账钩子摆在一起，第 6 问直接用它。类型套路写进了读者引擎卡就不算 AI 腔；不以“太常见”为理由撤掉读者冲着来的场面。

## 第二遍　连续性与语言

```text
先跑机器定位，再逐章人工核对：

python3 novel.py style <永久ID> --draft <草稿路径> --prompt
python3 novel.py repeat <永久ID> --card

1. 因果：每个结果都由正文里已有的行动和条件造成；阻力不能被一句正常解释绕开。
2. 数量与资源：时间、距离、金额能同时成立。人物报出总数时回到正文逐项数，
   写出「正文列出 N 项，人物说 M 项」。
3. 规则：打开固定设定 C 的特殊规则逐条核对，本章有没有违反、扩大或给出例外。
4. 知情：每条被使用的信息写出来源。人物不能用自己此刻还不知道的事。
5. 物件与位置：会累积状态的物件（单据、账户、钥匙、耗材）从上次出现到现在推演一遍。
6. 语言：机器命中逐条判断，有作用就保留；按包内文风档的「语言检查」核对情绪、
   内心与高光处的写法；去掉说话人标签后对话还能分出是谁；正文里没有永久 ID、流程术语或内部标记；
   系统提示和对话现实里会有人这么说，设定与账本里的条款限定（真实、结算、对应、本人……）不照搬进正文。

只列问题和位置。
```

机器定位只标位置，不打分。不要为了让命中数变少去改句子。

## 结构的简短核对

每批核对实际结果是否还接得上弧卡与后续安排。到达三章小审查、十二章或弧末复盘时，运行一次 `outline --prompt`，按需读 `16_大纲论证与滚动复盘.md`；复盘写出下一段至少一项加强措施或保留理由。改未来路线、旧章或核心设定走 revise。

## 统一修改与复读

按 因果 → 知情 → 连续性 → 追读 → 语言 的顺序改。改动事实、数值、位置或信息顺序后，回读所有依赖它的句子。最后把整批从头连读一遍。

## 提交前核对

- [ ] 三拍与章卡的必须信息都已出现，章末落在章卡写的钩子上
- [ ] 弧内每章登记正文成立的章末落点；自然收束按章卡类型说明登记，不虚构事件
- [ ] 大纲、快照、事实记录、伏笔表、悬念账和插件表互相一致
- [ ] 正文文件头的字数与状态正确，正文中没有内部标记
- [ ] 改写没有凭空增加或压缩时间，没有改变知情范围
- [ ] 已向作者完整展示整批正文、三拍摘要与候选清单；作者明确批准同一摘要后才正式提交
